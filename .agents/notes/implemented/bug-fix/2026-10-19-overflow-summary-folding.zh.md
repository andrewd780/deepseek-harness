# Agent Note: 溢出恢复会逐段并入提供方拒绝的摘要

Status: implemented

[English](2026-10-19-overflow-summary-folding.md) | 中文

## Problem

在自定义端点上，上下文溢出错误会结束当前轮次，重试和 `/compact` 都无法恢复会话。溢出恢复与 `compactNow()` 会用一次请求摘要除最新 surface 节点之外的全部内容：系统头节点、整个选定范围和压缩指令，并按策略的 `maxTokens`（默认 65,536）预留输出。真实溢出发生后，这个请求与被拒绝的请求大小相当；当最新节点短于指令，或服务器把请求的输出计入窗口时，它还会更大，因此提供方会以同样的理由拒绝它。没有 `compaction/summary-error` listener 能修复文本溢出，所以这次尝试以错误关闭，原始失败结束了轮次。内置 DeepSeek 路由之所以能恢复，只是因为它的会话请求预留 256,000 个输出 token，为 65,536 token 的摘要预留留出了空间。上下文窗口留空的 pi-ai 自定义路由会认为窗口是 262,144 token 并预留 32,768 个输出 token，因此当真实窗口更小时，它的恢复不可能成功。

## Decision

`dsh-compaction-basic` 为溢出恢复与 `compactNow()` 逐段并入可压缩范围。第一个事务就是此前使用的单次请求：在策略上限下摘要整个可压缩范围。当摘要请求因 `CONTEXT_WINDOW_EXCEEDED` 被拒绝，或在上限处被截断时，下一次请求会更小。若窗口拒绝时的上限高于被拒范围的路由定价，则上限降至该定价；否则范围预算减半，上限保持不高于预算。被截断的摘要会让范围预算减半，并保持原上限。后续事务在预算内摘要最长的、从最旧处开始的平衡前缀，且该前缀必须包含本流程自身检查点之外的历史，直到范围耗尽或没有前缀能放入预算为止。

每个事务都是普通的日志记录括号，因此事件类型、wire 字段和 Session 格式都不变，每个模型请求仍可从日志重建。生成上限通过 `SummarizationInput.maxTokens` 传递，并记录在 `compaction/summary` 上。一旦已有事务提交，预算放不下任何前缀，或手动压缩出现 `summary` 或 `changed` 失败时，返回已提交的进展；其他失败照常传播。压力压缩与 `compactRegion()` 仍在策略上限下只发送一次请求，能放入窗口的第一次尝试发送的请求与此前相同，因此 DeepSeek 路由和已有的录制会话都不受影响。[包 README](../../../../packages/compaction/compaction-basic/README.zh.md) 负责具体的运行规则。

## Alternatives considered

**解析提供方声明的窗口，并按它确定一次能放入的请求大小。** 暂缓：OpenAI 兼容、vLLM、llama.cpp 和 Anthropic 风格的错误常会声明上限，但各服务器措辞不同，有些服务器根本不声明，而计量器按每四个字符一个 token 的估算与服务器分词器相差几个百分点。按规范错误码减半适用于所有已分类的提供方；声明的上限以后可以缩短搜索，但不会取代它。

**独立摘要各段并保留每份部分摘要。** 暂不采用：它避免了重新摘要检查点，却会在 surface 上留下多份摘要，并改变恢复后的模型看到历史的方式。逐段并入复用了指令中已有的合并先前 `<compacted-summary>` 块的规则。

**摘要放不下时丢弃最旧的历史。** 不采用：不留摘要就丢弃历史违背了检查点的用途；逐段并入会为它替换的全部内容保留摘要。

**把第一次尝试的上限降到范围定价。** 不采用：这会改变 DeepSeek 路由已录制的摘要，并可能截断推理模型对一个当前能放入的短范围所写的摘要。

**以更少的预留输出重试会话请求。** 不在本范围内：会话请求的输出预留属于适配器和 agent 请求策略，而不属于压缩。

## Consequences

配置的窗口大于端点实际执行窗口的会话在溢出后仍可继续使用，`/compact` 也能缩减它。代价是每缩小一步要承担一次被拒请求，每段并入要承担一次摘要调用，并且第一段之后的每次并入都会重写上一个检查点，因此细节可能在多次并入中漂移。声明的窗口不会被修正：压力策略仍按适配器的 `contextWindow` 定价，所以之后的溢出仍会落到恢复时的逐段并入，而这种并入不会逐字保留任何近期历史。窗口拒绝可能把上限降到推理模型处理小范围所需的额度以下；此时被截断的摘要会让范围减半。由会话请求自身的输出预留引起的溢出，或由单独就超出窗口的最新节点、系统提示词或工具集引起的溢出，仍不在压缩能处理的范围内。

## Testing

`packages/compaction/compaction-basic/tests/provider-window-overflow.spec.ts` 在真实 agent loop 上驱动适配器：适配器声明一个窗口，却对包括摘要在内的每个请求执行更小的窗口，拒绝分别以抛出和流内两种方式送达，覆盖只检查提示词的服务器和预留输出的服务器。自动恢复会完成轮次；每次被拒后的摘要请求在提示词和上限上都不更大，且总量更小；每个括号都会关闭，失败的括号与被拒的摘要一一对应，记录的上限与 wire 上的一致；溢出后执行 `/compact` 能让下一次请求放入窗口；后续手动并入失败时会报告已提交的进展。它的全部 13 个用例在单次请求的实现上都会失败。`overflow-fold.spec.ts` 固定了先降上限的步骤、截断处理、不可分的最旧单元、部分进展、非窗口失败、事务提交后的持久化失败，以及逐段并入之间和进行中的取消。
